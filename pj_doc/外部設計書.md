# デジタル価格表システム 外部設計書

## 1. システム概要

### 1.1 システム名称
デジタル価格表システム

### 1.2 システム目的
商品価格管理の効率化と承認ワークフローによる品質向上を目的とした、商品マスタ管理システムです。

### 1.3 システム特徴
- サーバーサイド中心のアーキテクチャによる安定性
- Web Components による再利用可能なUI部品
- 承認ワークフローによる変更管理
- AI技術を活用した価格情報抽出機能

## 2. 機能概要

### 2.1 主要機能一覧

| 機能分類 | 機能名 | 概要 |
|---------|--------|------|
| 商品管理 | 商品一覧・検索 | 商品の検索・一覧表示・ページネーション・並び順管理 |
| 商品管理 | 商品詳細・編集 | 商品基本情報と価格履歴の管理・Web Components編集 |
| 商品管理 | 商品コピー | 既存商品をベースとした新規商品作成 |
| 商品管理 | 商品削除申請 | 商品の論理削除申請 |
| 価格管理 | 価格履歴管理 | 時系列での価格変更履歴管理・動的追加削除 |
| 価格管理 | 粗利率自動算出 | 県連価格の自動計算機能・手動設定対応 |
| 価格管理 | デジタル価格表 | 指定月時点での価格表表示・並び順管理・Excel出力 |
| ワークフロー | 申請管理 | 新規作成・更新・削除申請の管理 |
| ワークフロー | 承認処理 | 個別承認・一括承認・却下・申請取消機能 |
| ワークフロー | 差分表示 | 申請内容と現行データの比較表示 |
| AI機能 | 価格抽出 | JSON形式での価格情報抽出・商品マッチング |
| AI機能 | 商品マッチング | 2-gramアルゴリズムによる商品照合・スコア表示 |
| AI機能 | 抽出履歴管理 | AI抽出履歴の管理・論理削除・再照合 |
| マスタ管理 | 畜種・分類・メーカー | 各種マスタデータのCRUD操作 |
| システム管理 | データ管理 | エクスポート・インポート・一括処理（管理者限定） |
| 決裁書管理 | PDFアップロード | 月別決裁書PDFの管理 |

### 2.2 業務フロー

#### 2.2.1 商品登録フロー
```
商品一覧 → 新規登録 → 基本情報入力 → 価格履歴入力 → 申請 → 承認 → 登録完了
```

#### 2.2.2 価格改定フロー
```
商品詳細 → 価格履歴追加 → 改定内容入力 → 申請 → 承認 → 改定完了
```

#### 2.2.3 承認ワークフロー
```
申請一覧 → 申請詳細 → 差分確認 → 承認/却下 → 処理完了
```

#### 2.2.4 AI価格抽出フロー
```
AI価格抽出入力 → JSON処理 → 商品マッチング → 結果編集 → 申請 → 承認 → 価格履歴反映
```

#### 2.2.5 マスタ管理フロー
```
マスタ一覧 → 新規登録/編集 → 保存 → 一覧更新
```

## 3. 画面設計

### 3.1 画面構成

#### 3.1.1 メイン画面
- **ダッシュボード**: システムのメインメニュー・管理者権限制御
- **商品一覧**: 商品の検索・一覧表示・並び順管理
- **商品詳細**: 商品情報と価格履歴の管理・Web Components編集
- **デジタル価格表**: 月次価格表の表示・Excel出力
- **申請一覧**: 承認待ち申請の管理・一括処理
- **申請詳細**: 申請内容の詳細確認・差分表示

#### 3.1.2 補助画面
- **AI価格抽出**: JSON形式での価格情報抽出・商品マッチング
- **AI抽出履歴**: 抽出履歴の管理・論理削除
- **商品コピー**: 既存商品の複製作成
- **商品削除**: 商品削除申請
- **マスタ管理**: 畜種・分類・メーカーマスタのCRUD
- **決裁書管理**: 月別決裁書PDFアップロード
- **システム管理**: データ管理・一括処理（管理者限定）

## 4. データ設計

### 4.1 主要エンティティ

#### 4.1.1 商品マスタ (Product)
| 項目名 | データ型 | 必須 | 概要 |
|--------|----------|------|------|
| 商品番号 | Integer | ○ | システム自動採番 |
| 商品コード | String(50) | - | ユーザー管理用コード |
| 畜種 | String(50) | - | 対象畜種 |
| 分類 | String(100) | - | 商品分類 |
| メーカー | String(100) | - | 製造メーカー |
| 商品名 | String(200) | ○ | 商品名称 |
| 型式 | String(100) | - | 商品型式 |
| 規格 | String(100) | - | 商品規格 |
| 発送単位 | String(50) | - | 発送単位 |
| 送料 | String(100) | - | 送料情報 |
| 備考 | Text | - | 備考欄 |

#### 4.1.2 価格改定履歴 (PriceHistory)
| 項目名 | データ型 | 必須 | 概要 |
|--------|----------|------|------|
| 商品 | ForeignKey | ○ | 対象商品 |
| 年度 | Integer | ○ | 適用年度 |
| 適用年月 | String(7) | ○ | YYYY/MM形式 |
| 粗利率 | Decimal(10,6) | ○ | 粗利率 |
| 仕切価格 | String(50) | ○ | 仕入価格 |
| 県連価格 | String(50) | - | 販売価格（自動計算可） |
| 参考小売価格 | String(50) | - | 市場参考価格 |
| 改定理由 | Text | - | 価格改定理由 |

#### 4.1.3 承認テーブル
- **商品マスタ承認 (ProductApproval)**: 商品情報の申請データ
- **価格履歴承認 (PriceHistoryApproval)**: 価格履歴の申請データ

### 4.2 データ整合性

#### 4.2.1 業務ルール
- 商品番号は自動採番による一意性保証
- 価格履歴は商品ごとに時系列管理
- 論理削除による履歴保持
- 承認ワークフローによる変更管理

#### 4.2.2 制約条件
- 過去月の価格履歴は最新のもののみ編集可能
- 粗利率は年度ごとに管理
- 県連価格は粗利率による自動計算または手動設定

## 5. システム構成

### 5.1 アーキテクチャ

#### 5.1.1 システム構成
```
プレゼンテーション層
├── Web Components (UI部品)
├── Bootstrap (UIフレームワーク)
└── HTML Templates

ビジネスロジック層
├── Django Views (画面制御)
├── Django Forms (入力制御)
└── Business Logic (業務ロジック)

データアクセス層
├── Django Models (データモデル)
├── Django ORM (データアクセス)
└── SQLite Database (データストレージ)
```

#### 5.1.2 技術スタック
